# Support AI

**Корпоративный AI Service Desk** для технической поддержки Lamoda.

Support AI принимает обращения в Pachca, ищет инструкции в Яндекс Wiki, отвечает в треде с кнопками обратной связи и при необходимости создаёт тикет в Яндекс Tracker — с автоматической маршрутизацией по системе SD, локации, очереди и категории обращения.

**Текущая версия:** v0.7 (калибровка → v1.0 локально)  
**Стек:** Python 3, FastAPI, OpenAI-compatible LLM, Яндекс Wiki, Pachca, Яндекс Tracker

**Документация:** [docs/](docs/) — архитектура, roadmap, эксплуатация, стандартизация

> **Исходный код** — закрытый репозиторий, доступ только у команды Support AI / IT.  
> Этот репозиторий содержит описание продукта и документацию для обсуждения и презентаций.

## Возможности

- Поиск и ранжирование инструкций в Wiki (1–2 релевантные страницы), ссылки Wiki из сообщения, приоритетные slug
- Диалог в треде: история, ОС, интент (установка / troubleshoot / VPN), мульти-темы в одном сообщении
- Уточняющие вопросы: ОС, сервис, устройство Wi‑Fi, переговорки, «с чем вопрос?»
- Кнопки 👍 / 👎 / 🎫 с защитой (автор, один клик)
- **Создание тикетов** в Tracker от имени автора Pachca — очередь по **системе SD + локации** (SUPINT, SUPBYK, TECHCX, …)
- **Вложения** из Pachca → файлы в задаче Tracker
- **Статус задачи** в Tracker: в треде после тикета и из канала (ключ или ссылка)
- Сценарии: диагностика оборудования, переговорки, ITShop ≠ Tracker status
- Матрица 150 систем SD, keywords, категория по контексту диалога
- Обучение на feedback: отчёт gaps / keywords, секция на дашборде
- Дашборд аналитики (вкладки, фильтр по датам, KPI v1.0)
- Стабильность: watchdog, burst в канале, TTL сессий, реакция `agent-thinking`

## Архитектура

```text
Pachca (канал / тред)
        │
        ▼
  Webhook / poller
        │
        ├── dialogue   (уточнения, OS, intent, сценарии)
        ├── wiki       (ranking, 1–2 инструкции)
        ├── tracker    (статус задачи)
        └── llm        (ответ)
        │
        ▼
  Ответ в треде + кнопки (+ agent-thinking)
        │
        ├── 👍/👎 → feedback + analytics
        └── 🎫 / 👎 → локация → тикет (+ вложения)
                    │
                    ▼
              Yandex Tracker
              (очередь по SD + локации, поля, автор)
```

## Основной flow в Pachca

1. Пользователь пишет в канал (подряд идущие сообщения одного автора могут **склеиваться** — burst ~5 сек).
2. Бот создаёт **тред**, ищет 1–2 инструкции, отвечает с кнопками.
3. В треде — уточнения и смена ОС («у меня macOS»).
4. «Не помогло» / «Создать тикет» → **локация SD** → задача в **нужной очереди** + вложения из треда.
5. После тикета можно спросить **статус** (`SUPINT-123`, ссылка Tracker).
6. Из канала: «статус задачи» с ключом или запрос ключа/ссылки.

## Tracker: очереди и маршрутизация

**Создание задачи** — очередь из матрицы SD и локации.  
**Статус задачи** — отдельный список очередей (по умолчанию SUPINT, SUPBYK).

| Локация | Очередь |
|---------|---------|
| Центральный офис, Удаленно, КЦ Волгоград | SUPINT |
| РЦ Быково | SUPBYK |
| РЦ Софьино | SUPSOF |
| РЦ Чехов, ПВЗ, TWH, LaSport | TECHCX |
| BY | SUPBY |
| KZ | SUPKZ |

| Очередь | Примеры |
|---------|---------|
| SUPINT | VPN, Пачка, Wiki, Huntflow, GitLab |
| TECHCX | 1C, Verme, WMS, Axapta, Checkoffice |
| По локации | AD, 2FA, Диск Z, Yandex 360 |
